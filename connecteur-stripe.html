Paiement en ligne — Stripe

Encaissez vos clients en ligne et rapprochez automatiquement les règlements de vos factures. Chaque établissement dispose de sa propre adresse de notification (webhook) sécurisée.

01 Ce que permet le connecteur

Le connecteur Stripe relie vos paiements en ligne à la facturation Anim'Gest.

  • Encaisser en ligne les factures et acomptes via Stripe.
  • Rapprochement automatique : à chaque paiement confirmé, le règlement est enregistré sur la facture correspondante.
  • Notification sécurisée (webhook) : Stripe prévient Anim'Gest, la signature est vérifiée avant tout enregistrement.
  • Une adresse par établissement : l'URL de notification se termine par votre identifiant tXXXXXX.
  • Sans doublon : un même paiement n'est rapproché qu'une seule fois (traitement idempotent).
  • Conforme NF525 : le règlement s'inscrit dans la chaîne d'intégrité des factures.

03 Configurer le webhook

  1. Repérer votre identifiant

    Notez l'identifiant de votre établissement, au format tXXXXXX, visible dans l'URL de votre espace Anim'Gest. Il sera nécessaire à l'étape 3.

  2. Ajouter un endpoint

    Dans le Dashboard Stripe, ouvrez Développeurs › Webhooks puis cliquez sur Ajouter un endpoint.

  3. Coller l'URL par établissement

    Renseignez l'adresse de notification, propre à votre établissement : https://animgest-app-saas.no-sages-editor.com/api/stripe/webhook/tXXXXXX. Elle se termine par votre identifiant.

  4. Choisir l'événement

    Sélectionnez payment_intent.succeeded (paiement confirmé). C'est le seul événement nécessaire au rapprochement.

  5. Copier la clé secrète

    Validez la création. Stripe affiche la clé de signature, préfixée whsec_. Révélez-la puis copiez-la.

  6. Coller dans Anim'Gest

    Dans Paramètres › API › Stripe, collez la clé whsec_… et Enregistrez. Elle est chiffrée et n'est plus jamais réaffichée.

  7. Tester

    Déclenchez un paiement de test : Stripe envoie la notification et doit recevoir une réponse 200 OK. Le règlement apparaît alors sur la facture.
Bon à savoir. L'adresse du webhook est propre à chaque établissement. Ne réutilisez pas l'URL d'un autre établissement : elle se termine toujours par l'identifiant tXXXXXX correspondant.
04 Suivi & dépannage

Stripe affiche la réponse de chaque livraison de webhook. Codes attendus :

CodeSignification & action
200La notification a été reçue, sa signature vérifiée et le règlement rapproché. Rien à faire.
503Clé manquante. Aucun secret webhook n'est renseigné pour cet établissement — collez le whsec_… dans Paramètres › API › Stripe.
400Signature invalide. Le secret collé ne correspond pas à celui du endpoint — recopiez la bonne clé du bon endpoint.
400 · BAD_TENANTIdentifiant mal formé. L'URL ne se termine pas par un tXXXXXX valide — corrigez la fin de l'adresse du endpoint.
Idempotence. Si Stripe renvoie deux fois la même notification, le règlement n'est enregistré qu'une seule fois : aucun doublon sur la facture.
05 Bonnes pratiques
  • Mode Test d'abord pour valider la chaîne, puis passez en Live pour les encaissements réels.
  • Une URL par établissement : vérifiez que l'identifiant tXXXXXX de l'URL est bien le vôtre.
  • Après un premier paiement test, contrôlez que le règlement apparaît bien sur la facture.
  • Si vous changez d'endpoint, recopiez la nouvelle clé whsec_… dans Anim'Gest.
Confidentialité. La clé whsec_… authentifie les notifications de Stripe : ne la partagez jamais. Elle est stockée chiffrée et n'est plus réaffichée après enregistrement.
